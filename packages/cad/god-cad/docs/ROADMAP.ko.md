# 개발 순서와 완료 조건

달력 일정이나 정확도 수치는 아직 약속하지 않는다. 실제 도면과 ZWCAD 환경이 없는 단계에서는 작업별 통과 조건으로 관리한다.

## 단계와 의존성

| ID | 작업 | 선행 | 완료 증거 |
| --- | --- | --- | --- |
| S00 | v0.1 뼈대 | 없음 | DXF/JSON/SVG 데모, 계획 통과·거부 테스트, CI |
| G01 | DXF inventory/identity 확장 | S00 | layout·block instance·OCS·미지원 범위가 드러나는 합성 fixture와 회귀 테스트 |
| G02 | ZWCAD 환경 검증과 native 읽기 | S00 | 실제 SDK 빌드·호스트 로드·읽기 명령·추출 결과; DWG 무변경 증거 |
| G03 | native↔DXF 매핑·차이 보고서 | G01, G02 | 동일/누락/모호한 객체 매핑, provenance, 허용오차 및 누락율 보고 |
| G04 | 의미 객체 그룹·공간·온톨로지 정렬 | G01 | 여러 primitive→벽 후보, 문/공간 후보, 검토 상태·근거·RDF 매핑 테스트 |
| G05 | 제한된 native 편집·재검증 | G03 | 합성 DWG에서 독립 객체 이동→저장→재열기→원본·비대상 보존 검사 |
| G06 | 객체별 편집 규칙 | G04, G05 | 벽 편집 시 인접 선 연장/절단, 문 호스트, 치수/해치 갱신 또는 명시적 거부 |

| G08 | 실제 도면 평가와 지원 범위 확대 | 각 기능 단계와 함께 | 격리한 평가 세트, 실패 분류, 크기별 성능, 지원 매트릭스 |

S00 이후 바로 할 일은 G01이다. 별도의 Windows CAD 환경 담당자가 있으면 G02를 독립적으로 진행할 수 있다. G03의 계약이 안정되기 전에 DWG writer를 구현하지 않는다.

## 첫 동작 가능한 제품의 범위

첫 실사용 후보는 **확인된 하나의 ZWCAD 버전, 명시된 2D 모델 공간 객체, 제한된 이동 연산**이다. 성공은 파일이 저장됐다는 사실만으로 판단하지 않는다. 입력 revision과 대상이 일치하고, 기대 변경 외 데이터가 유지되고, 저장 후 열리고, 정해진 검증이 모두 수행돼야 한다.

초기 제외 범위: 임의 3D, proxy/vertical 객체의 자동 변환, Xref 내부 편집, 동적 블록 일반 해석, 모든 치수 스타일, 전체 BIM 재생성, 설계 의도/규정 적합성 자동 보장. 제외한 객체는 발견·보존·보고해야 한다.

## G08 평가 지표

- 추출: 도면별 scope, CAD 종류별 원본 수/추출 수/미지원 수, 매핑 ambiguity, 단위·변환 오차.
- 의미: 클래스·회사·도면 종류별 precision/recall, instance grouping, 미확정 비율과 잘못 확정한 비율.
- 위상: endpoint, intersection, containment, room adjacency별 검출·누락 사례.
- 편집: 명령별 성공률, 잘못된 계획 거부율, 예상 밖 변경 수, 실패 후 원본 유지 여부.
- 검증: 필수 검사 중 실행한 수, 누락된 검사, native 재열기, 파서 간 차이, 고정 렌더 설정의 변화 영역.
- 성능: 객체 수별 시간·최대 메모리·산출물 크기. 현재 O(n²) 위상 구현은 대형 도면 성능 기준이 아니다.

임계값은 실제 허용 단위와 평가 fixture를 정의한 뒤 고정한다. 0.1 mm는 현재 endpoint 데모의 파라미터이며 제품 전반의 정확도 보증이 아니다.

## 아직 필요한 환경·의사결정

정확한 ZWCAD 설치 버전/SDK, 권한이 있는 대표 DWG 세트, 대상 도면 규칙, 허용되는 최초 편집 명령, 코드 배포 라이선스는 후속 단계에서 확정한다. 이 정보가 없더라도 코어·합성 fixture·계약 작업은 진행할 수 있다. 상용 SDK 구매와 실도면 외부 전송은 현재 계획에 포함하지 않는다.
