# ChatGPT(iOS) MCP 검토 흐름 E2E 체크리스트 (Issue #71 G)

Issue #71 G단계 "모바일 OAuth 로그인 → 프로젝트 선택 → 근거 읽기 → 사람 검토 → 서버 기록 읽어보기"를
자동 테스트와 수동 점검으로 나눈다. CI 성공은 실사용 성공이 아니다. 아래 수동 체크리스트를 실제
iPhone에서 통과해야 G단계를 닫는다.

## 현재 상태 (자동화 범위)

- Sion 지식용 MCP 서버는 아직 없다. `packages/aec`의 `aec_intelligence.mcp_stdio`/`mcp_http`는
  AEC/CAIR 게이트웨이 전용이고, localhost에만 바인딩되며 OAuth가 없다.
- 그래서 자동 E2E는 MCP 어댑터가 호출할 Sion HTTP API(`apps/api/sion_api`)를 대상으로 한다.
  `tests/test_mcp_review_e2e.py`가 MCP JSON-RPC `tools/call` 형식의 인프로세스 어댑터 대역과
  FastAPI `TestClient`로 네트워크 없이 다음을 검증한다.
  - 읽기 토큰(`read:knowledge`)과 쓰기 토큰(`read:knowledge` + `write:knowledge`)을 분리해 전체 흐름 수행
  - 읽기 전용 토큰의 approve/reject/bulk/reopen/evidence 쓰기는 서버가 403, 토큰 없음/미등록 토큰은 401
  - 허용되지 않은 프로젝트는 어댑터가 API 호출 전에 거부(요청 기록이 비어 있음을 확인)
  - 다른 프로젝트의 후보 id를 허용 프로젝트 경로로 넣어도 읽기·쓰기 불가
  - 신뢰도 0.99 후보도 읽기만으로는 승인되지 않고, `human_confirmed: true`와 메모 없는 결정은 전달되지 않음
  - 기록된 결정(검토자, 메모, 이전 상태, 근거 상태)을 읽기 토큰으로 다시 읽을 수 있고, 두 번째 결정은 409
- 서버에는 아직 프로젝트 ACL이 없다(Issue #71 C단계). 프로젝트 허용 목록은 어댑터 쪽 게이트이며,
  실제 어댑터를 만들 때 이 게이트와 테스트를 그대로 유지하거나 서버 ACL로 옮긴 뒤 테스트를 갱신한다.

실행: `uv run --frozen --extra test pytest -q tests/test_mcp_review_e2e.py`

## 수동 체크리스트 전제

- 스테이징 MCP 엔드포인트(HTTPS, 리뷰된 프런트 도어 뒤)와 OAuth 2.1 인가 서버가 준비되어 있다.
  프로덕션 데이터로 시작하지 않는다.
- 테스트 계정 두 개: 읽기 전용 계정(`read:knowledge`, 프로젝트 A만 허용), 검토자 계정
  (`read:knowledge` + `write:knowledge`, 프로젝트 A만 허용). 프로젝트 B는 두 계정 모두 금지.
- 프로젝트 A에 합성 후보 2건 이상(신뢰도 높은 것 1건 포함)과 근거, 프로젝트 B에 후보 1건.
- 토큰, 클라이언트 시크릿, 엔드포인트 실제 주소, 계정 이메일은 이 문서·이슈·PR·스크린샷에 남기지 않는다.
  결과 기록에는 `<staging-endpoint>`, `reader@`, `reviewer@` 같은 자리표시자만 쓴다([SECRETS.ko.md](SECRETS.ko.md)).

## 수동 체크리스트 1: 연결과 OAuth 로그인 (읽기 계정)

- [ ] iPhone ChatGPT 앱 최신 버전에서 커넥터(MCP) 추가 화면으로 스테이징 엔드포인트를 등록한다.
- [ ] 인가 화면이 Safari/인앱 브라우저로 열리고 인가 서버 도메인이 예상 도메인과 같다.
- [ ] 동의 화면에 요청 범위가 `read:knowledge`만 표시된다(쓰기 범위 없음).
- [ ] 로그인 후 앱으로 돌아오고 도구 목록이 보인다. 실패 시 다시 시도해도 토큰이 대화에 노출되지 않는다.
- [ ] 서버 로그에 PKCE(S256) 사용, redirect URI 정확 일치, 토큰 audience가 MCP 리소스로 기록된다.

## 수동 체크리스트 2: 프로젝트 선택과 근거 읽기

- [ ] "내 프로젝트 목록"을 요청하면 프로젝트 A만 보인다.
- [ ] 프로젝트 B의 이름이나 id를 직접 말해 조회를 요청하면 거부되고, 서버 로그에 B 데이터 조회가 없다.
- [ ] 프로젝트 A의 대기 후보 목록과 한 후보의 근거(출처, 위치, 발췌)를 읽을 수 있다.
- [ ] 응답에 원본 경로, Drive 식별자, 개인 정보가 들어 있지 않다.

## 수동 체크리스트 3: 읽기 계정의 쓰기 거부와 자동 승인 금지

- [ ] 읽기 계정으로 "이 후보 승인해줘"를 요청하면 거부된다(서버 403). 후보 상태는 그대로 pending이다.
- [ ] ChatGPT가 근거를 요약하거나 승인 의견을 내도 사람 확인 없이 결정 도구가 호출되지 않는다.
- [ ] 높은 신뢰도 후보도 조회만으로 승인 상태가 되지 않는다.

## 수동 체크리스트 4: 검토자 계정의 사람 검토 결정

- [ ] 연결을 끊고 검토자 계정으로 다시 OAuth 로그인한다. 동의 화면에 `write:knowledge`가 따로 표시된다.
- [ ] 후보 하나를 메모와 함께 승인 또는 거절한다. 결정 직전에 ChatGPT의 도구 실행 확인 화면에서
      사람이 직접 확인한다.
- [ ] 같은 후보에 다른 결정을 다시 요청하면 충돌(409)로 거부되고 첫 기록이 유지된다.
- [ ] 프로젝트 B 후보에 대한 결정 요청은 쓰기 계정이라도 거부된다.

## 수동 체크리스트 5: 서버 기록 읽어보기

- [ ] 읽기 계정으로 다시 전환해 같은 후보의 결정 기록(결정, 검토자, 메모, 시각, 이전 상태)을 읽는다.
- [ ] PC의 `/review` 화면 또는 API에서도 같은 기록이 보인다.
- [ ] 결정하지 않은 후보는 모두 pending이다.

## 수동 체크리스트 6: 토큰 수명과 철회

- [ ] 액세스 토큰 만료 후 재인증 또는 refresh가 동작하고, 만료 토큰으로는 401이 난다.
- [ ] 인가 서버에서 검토자 계정 권한을 철회하면 다음 쓰기가 401/403이 된다.
- [ ] ChatGPT에서 커넥터를 제거하면 세션이 더 이상 도구를 호출하지 못한다.
