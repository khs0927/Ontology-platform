# 중첩 건축·토지 규제 시스템 벤치마킹

조사일: 2026-10-11. Exa Search 스킬로 10개 조사 방향에서 검색 결과 80건을 요청하고 검토했다. 이 수는 중복을 포함한 검색 범위이며, 서로 다른 시스템 80개를 실사했다는 뜻이 아니다. 공식 문서·원저자 저장소를 우선하고, 핵심 17개 URL의 본문과 일부 GitHub 원본 코드를 추가 확인했다. 외부 코드를 설치하거나 실행하지 않았고, 실서비스 API의 응답 정확도·전국 커버리지는 아직 검증하지 않았다.

## 결론

이 프로젝트는 새 GraphRAG 엔진을 만드는 것보다 **공식 규제 연결 데이터 + 기존 한국 MCP + 플랫폼의 ArchOntos/LightRAG**를 통합하는 편이 맞다. 국내 규제 데이터의 연결관계와 건축 규칙을 형식화하는 방법이 이미 존재한다. 다만 이를 한국의 필지·계획·행위·시점에 맞춰 연결하고, 누락과 불확실성을 검증하는 어댑터는 필요하다.

## 가장 적합한 선행 워크플로우

토지이음의 [서비스 안내](https://www.eum.go.kr/web/lc/bi/biServiceIntro.jsp)는 토지이용계획, 도시계획, 규제안내서, 고시정보를 구분한다. 이 구성을 작업 브리핑에도 적용하면 지도나 상태 숫자보다 실무에 유용하다.

제안하는 연결 순서는 다음과 같다. 이는 조사 자료를 현재 플랫폼에 맞춰 종합한 설계안이며, 구현 완료 상태가 아니다.

1. **필지 확정:** 주소→PNU→필지 경계. 경계가 여러 지역지구에 걸치면 해당 부분을 모두 보존한다.
2. **지정 사실 수집:** 국계법상 용도지역·지구·구역과 다른 법률상 지정, 지목, 지구단위계획, 고시를 모은다. 수집일과 사실의 유효기간을 따로 기록한다.
3. **공식 연결관계 조회:** 관할지역·지역지구·제안 행위를 공식 규제 데이터에 연결해 관련 조문 후보를 얻는다.
4. **법령 관계 확장:** 체계도·위임·조례 연결·인용 조문·별표·부칙을 따라간다. 참조 관계와 실제 적용 관계를 다른 유형으로 저장한다.
5. **적용조건 확인:** 용도, 개발행위, 면적, 규모, 허가 시점 등을 RASE의 적용조건·선택·요구사항·예외로 정리한다. 누락 사실은 추가 확인 작업으로 남긴다.
6. **시간·관할·충돌 검토:** 시행일, 경과조치, 조례, 지구단위계획과 개별 법률의 적용 범위를 함께 확인한다. 법령 간 우선성은 원문 조항과 적용조건으로 뒷받침한다.
7. **검색·판정·브리핑:** LightRAG가 근거를 찾아 설명하고 ArchOntos의 검토된 규칙이 평가한다. 근거, 예외, 미확인 항목, 다음 작업을 프로젝트에 저장한다.

온톨로지의 최소 객체는 필지, 지정사항, 관할, 계획/고시, 제안행위, 법령, 법령버전, 조문, 별표, 적용조건, 예외, 해석례, 근거, 검토 작업이다. 관계에는 지정됨, 관할함, 제한함, 위임함, 인용함, 예외로함, 개정함, 근거로뒷받침함이 필요하다. 모든 관계에 원문 위치·버전·유효기간·검토상태를 연결한다.

## 그대로 복사하면 안 되는 부분

[korean-land-mcp의 실제 코드](https://github.com/UrbanWatcherKr/korean-land-mcp/blob/main/src/tools/analyze_parcel.ts)는 레이어별 governing_law와 triggers_priority_delegation을 수동 지정한다. 따라서 후보 추천과 조회 흐름을 벤치마킹하되, 모든 후보를 국계법 제76조 제5항의 우선 적용 법령으로 일괄 취급하는 문구는 검증 없이 사용하지 않는다. API 실패나 레이어 미지원 때문에 결과가 비어 있을 때도 비해당을 확정하면 안 된다.

[ACCORD NLP 설명](https://docs.accordproject.eu/nlp/)에서 SNOWTEC은 외부 참조나 미해결 표현이 없는 독립적인 문장을 주요 대상으로 삼는다. 한국 법령의 “다만”, “별표”, “대통령령으로 정하는”, 다른 조항 준용은 참조 해소와 검토가 추가로 필요하다.

[공식 토지이용계획 열람 유의사항](https://kras.gg.go.kr/land_info/info/landuse/landuse.do)은 모든 법령 제한을 망라하지 않고 일부 지정 여부도 확인하지 못한다고 설명한다. 따라서 공식 데이터도 커버리지와 누락을 표시해야 한다. 모든 호출 성공을 법규 검토 완결로 간주하지 않는다.

## 현재 레포에서 먼저 재사용할 것

로컬 소스를 확인한 결과 Ontology-platform/packages/regulation의 ArchOntos에는 근거 정규화·버전·적용성/관할/시점 질의·검토된 assertion 기반 rule compiler·PASS/FAIL/REVIEW 평가 기반이 이미 있다. packages/graphrag에는 LightRAG 래퍼와 DB의 entity/relation/evidence를 custom KG로 투영하는 함수가 있다. 기존 구현의 존재를 확인했으며 이번 조사에서 전체 통합 실행을 다시 검증한 것은 아니다.

따라서 직전에 시작한 별도 키워드 법령 카탈로그와 간단한 그래프 검색을 핵심 엔진으로 확대하지 않는다. 변경 파일은 보존했지만 추가 구현·배포는 하지 않았다. 먼저 기존 적용성 모델에 공식 규제 연결 데이터를 적재하고, 현재 MCP 계약에 토지/법령 MCP를 맞추는 것이 우선이다. JEV 제외는 사용자 요구로 유지하되 이번 조사에서는 실행 경로를 변경하거나 검증하지 않았다.

## 다음 구현의 완료 기준

- 공식 CSV/API 샘플의 필드·코드·중복·공란·갱신일을 확인하고 법제처 식별자로 연결한다.
- MCP별 커밋, 라이선스, 도구 스키마를 고정한다. 기존 외부 MCP 계약과 호환되도록 어댑터만 추가한다.
- 농지, 산지, 농지+산지 중첩, 지구단위계획, 관할 조례, 과거 허가 시점, 외부 API 실패 사례를 준비한다.
- 각 사례의 기대 필수 법령·조문과 필수 사실을 사람이 검토한 기준으로 지정한다. 필수 근거 누락률, 추가 검색 이유, 버전 적합성, 지연·비용을 측정한다.
- 근거 미수집을 비해당으로 오인하지 않는지 검증한다. 예외나 우선관계가 확인되지 않으면 REVIEW로 남긴다.
- 브리핑에 적용 후보와 확인된 적용 근거, 원문, 예외, 미확인 사실, 다음 작업을 구분해 저장한다.

이번 조사로 재사용 후보와 설계 방향은 좁혔다. 설치·라이브 API 비교·국내 규칙 정확성 검증은 다음 단계에 남아 있다.
