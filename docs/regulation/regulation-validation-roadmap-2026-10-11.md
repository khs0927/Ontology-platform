# 검증 시나리오와 개발 단계별 완료 기준

작성일: 2026-10-11 · 계획 문서 · 아래 시험과 개발은 아직 실행하지 않았다.

## 1. 검증의 단위

각 기준 사례는 필지/부분, 제안행위/용도/규모, 사건 날짜, 관할, 원문 snapshot, 필수 사실, 기대 법령·조문·별표·부칙, 예외, 예상 누락/충돌, 검토자 역할과 검토일을 갖는다. 기대 결과는 실제 자료를 검토한 뒤 확정한다. 가상 사례에 실제 법적 정답을 붙이지 않는다.

데이터셋은 다음을 분리한다.

- 처리 계약 시험: 공급자 응답 형태·버전·해시·페이징·실패 처리.
- 의미 검증 사례: 사람이 검토한 적용 법규·예외·관할·시점 기준.
- 회귀 사례: 발견한 실제 결함을 재현하는 최소 자료.
- 독립 평가 사례: 튜닝에 쓰지 않은 관할/필지/질문.

민감한 주소·문서는 공개 fixture에 그대로 넣지 않는다. 공개 가능한 공식 원문과 합성 식별자를 사용하고 사유자료 사례는 별도 접근권한으로 보관한다.

## 2. 기준 시나리오

| ID | 입력/문제 | 필수 기대 동작 |
|---|---|---|
| S01 | 주소가 여러 필지 후보로 해소 | 임의 첫 필지 선택 금지, 후보/확인 작업 |
| S02 | 필지 일부가 다른 용도지역에 교차 | 부분별 지정/근거 보존, first hit만 사용하지 않음 |
| S03 | 좌표계 변환/경계 오류 또는 점만 존재 | precision·계산 오류 표시, 정확한 부정 확인 금지 |
| S04 | 농업진흥지역 후보 | 법률상 농지·행위 사실 확인과 관련 조문/절차 후보 |
| S05 | 산지 관련 후보 | 지목/지번과 법률상 산지 구분, 관련 지정·행위 근거 |
| S06 | 농지·산지·국계법이 중첩 | 관련 법을 병행 검토, 하나의 우선 플래그로 종료 금지 |
| S07 | 지구단위계획구역, 계획 원문 없음 | 필수 결정조서/도면 미수집 표시, 허용 확정 금지 |
| S08 | 관할 조례와 중앙 법령 | 실제 위임·조례 조문과 관할 확인, 같은 이름 타지역 배제 |
| S09 | 같은 행위에 추가 환경/하천 등 후보 | 다른 법률 지정 범위·후속 확인 작업 생성 |

| S13 | 예외에 필요한 사실 미입력 | 예외 false로 대체 금지, unresolved/REVIEW |
| S14 | 별표·준용·정의 조문이 순환 인용 | 식별자별 중복 방지, 필요한 참조 유지, 상한 표시 |
| S15 | 법령명이 개정/폐지/동명 | 공식 지속 ID와 버전 ID로 구분 |
| S16 | 응답 조문번호와 요청 번호 불일치 | evidence 채택 거절, 재조회/오류 작업 |
| S17 | 두 근거가 같은 주제에서 상충 | 상충 근거 보존, 근거 없는 승자 결정 금지 |
| S18 | 두 제한이 다른 주제/대상 | 불필요한 conflict 대신 병행 평가 |
| S19 | API 429/5xx/권한 실패 | 구분된 오류·재시도 정책·부분 결과·누락 장부 |
| S20 | 레이어 결과 상한·다음 페이지 있음 | truncated, 후속 페이지 작업, 완결 표시 금지 |
| S21 | 원문 표/OCR 숫자·단위 오인 | 원문 위치 대조, 검토 전 실행 규칙 금지 |
| S22 | 설계에서 관측 층수만 제공 | 건물 전체 층수로 승격 금지, 사실 provenance 유지 |
| S23 | 모델이 관련 법령/인용을 만들어냄 | 실제 evidence ID/원문 검증 실패, 해당 주장 제외 |
| S24 | 검토 안 된 관계가 그래프에 존재 | 후보 설명과 평가 근거 분리 |
| S25 | 다른 프로젝트 사유자료와 유사한 질문 | 권한 없는 검색/인용 0건 |
| S26 | 동일 run 저장 재시도 | 같은 revision은 중복 저장 없음, 다른 payload의 key 충돌 거절 |
| S27 | 서버가 근거 저장 후 중단 | checkpoint·outbox 재처리, 자료 누락/중복 평가 방지 |
| S28 | 원문 변경 후 기존 보고서 열람 | 당시 snapshot 유지, 새 재검토 revision 연결 |
| S29 | 취소 후 진행 중 응답 도착 | 취소된 run에 새 완료 결론을 덮어쓰지 않음 |
| S30 | 생성/임베딩 모델 미설정·장애 | 결정적 근거 조회·평가·구조화 브리핑 사용 가능 |
| S31 | JEV 서비스 불가 | 규제 경로의 계획/조회/저장 정상, 플랫폼 권한은 유지 |
| S32 | CAD 등 다른 라우터 경로 | 기존 정책과 계약에 의도치 않은 변경 없음 |

## 3. 지표와 출시 문턱

아래 수치는 제안하는 출시 기준이다. 측정 결과가 아니며 전체 한국 법규에 대한 보증도 아니다.

| 지표 | 정의 | 제한 출시 기준 |
|---|---|---|
| 필수 근거 recall | 기준 사례의 필수 법령/조문/별표/부칙 중 확보·검증한 비율 | 한정된 출시 golden set에서 100%; 1건 누락도 원인 해소 |
| 근거 없는 확정 | 미검토 규칙/부재 사실/미해결 예외로 허용·비해당 결론 | 0건 |
| 인용 적합성 | 실제 원문·버전·조문 위치·주장과 연결 확인 | 확정 주장 100% trace 가능 |
| unknown 보존 | 실패/빈값/상한을 비해당으로 오인 | 0건 |
| 관할·시점 적합성 | 평가가 잘못된 관할/법령버전/경계를 사용 | 0건; 불확실한 경우 REVIEW |
| 사유자료 격리 | 권한 없는 project 문맥/인용 노출 | 0건 |
| 재현성 | 동일 snapshot·사실·규칙·평가버전의 결정적 결과 | 100% 동일; 생성 문장 동일성은 요구하지 않음 |
| 재시도/복구 | 완료 node 재사용, 저장 중복 방지, checkpoint 복구 | S26–S29 통과 |
| 부분 결과 진실성 | 미수집 원인과 다음 수집 작업 표시 | 모든 필수 누락 항목 표시 |
| 작업/브리핑 | 저장 후 readback, 원문 링크, 다음 작업, revision | 수동/자동 검증 모두 통과 |

후보 검색 precision은 별도 측정하고 자료 호출량과 검토 부담을 줄이는 데 사용한다. 필수 근거를 줄여 precision을 높이지 않는다. 지표의 분모는 확정된 범위와 기준 사례로만 계산한다.

초기 성능 목표 가설:

- 캐시된 원문/작업 읽기: p95 2초 이내.
- 단순 필지 검토: p95 45초 이내 결과 또는 run ID/부분 결과 반환.
- 대량 참조·여러 필지 검토: 비동기 실행, 진행/재개 조회 제공.
- 동시성·타임아웃·쿼터·문서 크기·재시도 예산은 공급자별 프로필로 설정.
- 비용은 1회 검토의 요청 수, 임베딩/생성 토큰, 색인 갱신량으로 측정. 금액 상한은 실제 모델·공급자 확인 후 정한다.

이전 턴의 키워드 planner, 간단 그래프 검색, 로컬 JEV 우회 초안은 검증된 구현으로 취급하지 않는다. 개발 착수 후 새 설계와 대조하여 유지/교체/폐기 결정을 기록한다. 검토 없이 덮어쓰거나 배포하지 않는다.

## 6. 위험과 대응

| 위험 | 조기 확인 방법 | 대응 |
|---|---|---|
| 다른 법률상 지정 범위 부족 | 규제 프로필과 공급자 catalog 대조 | 미지원 항목을 작업으로 표시, 출시 범위 제한 |
| 과거 지정 자료 부재 | 공급자 역사 조회/고시 확인 | 현재자료를 대체 사용하지 않고 unresolved |

| 적용/예외/의제 오판 | 법규 검토자 기준 사례 | 자동화 범위 축소, REVIEW |

| private/candidate 데이터 검색 혼입 | S24/S25, projection policy 검토 | 필터 선적용, 별도 색인/namespace |
| MCP 텍스트 결과 잘림 | 제한/페이지/metadata 계약 확인 | truncation 장부, 원문 별도 조회 |
| 분산 저장 일부 실패 | 중단/재처리 시험 | outbox/inbox와 영수증, 재개 |
| 의존성 호환/라이선스 | pinned source/lock/imports 확인 | 기존 버전 우선, 업데이트 별도 검증 |
| 쿼터/지연/비용 증가 | 실행 node별 계측 | 캐시·동시성 제한·비동기·예산 프로필 |

## 7. 운영과 롤백의 완료 기준

- 로그/metrics에 run/node, 공급자, 상태, 재시도, 누락, 원문 신선도를 남기고 비밀키를 제거한다.
- 원문과 규칙 버전, 평가 기록, outbox checkpoint를 백업/복구할 수 있다. 검색 색인은 재구축한다.
- 마이그레이션은 이전 스키마/소비자와의 호환 기간을 정한다. 초기에는 병행 읽기 비교 후 쓰기를 전환한다.
- 새 planner/투영/생성 기능은 독립적으로 끌 수 있다. 꺼도 저장된 원문·검토 기록을 열 수 있다.
- 롤백 후 새 버전 결과를 이전 실행에 덮어쓰지 않는다. 실패 revision은 그대로 보존한다.
- 출시 기록에 관할·행위·자료 범위, 미지원 규칙, 검토자, 기준 사례 결과, 공급자 pin, 운영 복구 결과를 포함한다.

## 8. 계획 단계의 마감 상태

완료: 전체 구조, 소유권, 온톨로지, 자료/사실/해석 분리, 중첩 규제 발견·적용·평가 흐름, MCP 계약안, GraphRAG 경계, 부분/복구/변경영향 정책, 작업 화면, 검증 기준, 개발 순서.

아직 미실행: 공식 키 권한 확인, 실제 샘플 적재/라이브 비교, 최종 관할·필지 기준 사례, 법규 검토 승인, 라이브러리/DB 호환 시험, 개발·설치·배포.

후속 지시 전에는 개발을 시작하지 않는다. 확인이 필요한 항목은 [프레임워크 본문 D01–D10](regulation-framework-plan-2026-10-11.md)에 기본안·확인 방법·영향을 남겼다.
