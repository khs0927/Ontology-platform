## 현재 작업 경계

계획 문서는 검토 가능한 설계이며 구현 완료 선언이 아니다. 이번 단계에서 허용되는 작업은 조사·문서 작성·문서 검증·문서 공개다. 사용자에게서 개발 착수 지시를 받기 전에는 소스 구현, 의존성 설치, DB 마이그레이션, 서버 재시작 또는 배포를 시작하지 않는다. 이후 명시적인 착수 지시가 있으면 그 지시가 이 보류 상태를 대체한다.

이전 개발 브랜치와 로컬 미완성 변경은 보존한다. 해당 변경을 계획 문서와 함께 무검토로 커밋하거나 배포하지 않는다. 벤치마킹에서 확인한 기능과 구현 현황은 조사 당시의 개발 체크아웃 또는 upstream에 관한 것이며 `main`의 배포 상태와 같지 않을 수 있다.

## 고정 원칙

- 공식 지역지구·관할·행위 연결 데이터를 법령 후보 생성의 기반으로 사용한다. 키워드 카탈로그만으로 검토 범위를 완성하지 않는다.
- 국계법·농지법·산지법과 조례·지구단위계획·별표·부칙을 대상/행위/시점별로 병행 검토한다. 한 법령의 존재로 다른 제한이 사라진다고 추정하지 않는다.
- 수집 사실, 해석 후보, 검토된 적용 관계, 규칙 평가를 구분한다. API 빈 결과·실패·결과 상한은 비해당의 근거가 아니다.
- ArchOntos가 규제 원문·assertion·규칙·평가 기록을 소유하고, 플랫폼 프로젝트는 이를 참조/투영한다. 중복된 평가 원장을 만들지 않는다.
- 기존 LightRAG를 재사용한다. 검색 전에 권한·프로젝트·시점·버전·검토상태를 제한한다. 검색 결과만으로 법적 허용 결론을 만들지 않는다.
- 외부 MCP의 우선 적용 힌트는 후보로 취급하고 원문 조항·조건·주제·관할·기간으로 검증한다.
- JEV는 건축규제 경로에서 제외하는 목표다. 기존 인증·프로젝트 권한·dry-run·감사와 저장 readback은 유지한다. 다른 CAD/Revit 경로의 정책을 함께 바꾸지 않는다.
- 새 엔진·DB·언어 도입 전에 기존 ArchOntos, LightRAG, 공식 API와 MCP 처리 흐름을 재사용할 수 있는지 확인한다.
- 외부 코드를 도입할 때 전체 commit, 실제 도구 스키마, 라이선스와 시험 결과를 고정한다. 파일 blob SHA를 repository commit pin으로 오인하지 않는다.
- 개발 착수 후에도 필수 근거·적용조건·예외·관할/시점·인용·격리·재개 기준을 통과하기 전에 해당 범위의 허용 기능을 출시하지 않는다.

## 개발 착수 시 첫 산출물

착수 지시를 받으면 바로 기능 코드를 늘리기 전에 D01–D10 준비 상태와 W01–W04 결과를 정리한다. 최초 검증 관할/행위, 공식 자료 계약, MCP 생산자/버전, 법규 기준 사례, 현행 라이브러리 호환성을 확정한다. 미확정 항목은 영향과 담당 확인 작업을 표시한다.

## 문서 관리

이 디렉터리가 전체 계획의 기준 문서 위치다. Gateway에는 이 지침을 연결한 짧은 진입 문서만 둔다. 책임 경계·계약·검증 기준이 바뀌면 본문과 개발 지침, 관련 통합 계약을 함께 갱신한다. 날짜가 붙은 조사 기록은 당시 확인한 자료로 보존하고 새 조사 결과를 구분한다.
