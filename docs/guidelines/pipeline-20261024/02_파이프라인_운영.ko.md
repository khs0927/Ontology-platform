# 02. 파이프라인 운영 순서

흐름: **법규·대지분석(MCP) → SketchUp 매스 → IFC4 → Revit(지음 템플릿) → 지음 시트 DWG**

## 0. 사전 확인
- `C:\Users\khs09\grokbot-mcp-bridge`에서 `node cad-check.cjs` → 5/5 PASS (rvt-mcp, horizun-revit, power-cad, sketchup-mcp2, hueflow). 앱이 켜져 있어야 함.
- 라우터: `start-router.ps1` 실행 후 8010 응답 확인.

## 1. 법규·대지분석
1. 주소/PNU 확정: korean-land `resolve_parcel`.
2. 용도지역: `get_zoning`, site-pipeline `land_characteristics`, `land_use_plan`(걸침 여부).
3. 형상: site-pipeline `parcel_geometry`(EPSG:5186 GeoJSON 저장).
4. 밀도: `site_compliance`(시행령 상한, 조례 미반영 → 조례는 따로 확인).
5. 도로: `road_profile`, `layer_overlap LT_C_UPISUQ151` (도시계획도로만 잡힘 → 현황도로는 수동 확인).
6. 지형: DEM(Copernicus GLO-30 등) → `dem_to_landxml`, 등고선 DXF → `contours_to_landxml`.
7. 전체: `run_pipeline` → `work\runs\<run_id>\manifest.json`.
8. 기상·일조: open-meteo, aec-solar(동지 그림자 등).
결과 JSON은 `C:\CODE\grokbot-handoff\site-calls-YYYYMMDD\`에 `*.args.json`/`*.out.json` 쌍으로 저장(온톨로지 수집기가 읽음).

## 2. SketchUp
- `ZIUM_template_tags.skp`(태그 12종) 기준으로 시작. 태그는 그룹에만 준다.
- 매스 생성은 sketchup-mcp2 또는 hueflow `execute_ruby`. **면 1.5만 개 넘는 모델은 멈춤** → 단순 매스로 작업.
- IFC4로 내보내기(`*.ifc` + 로그).

## 3. Revit
- `ZIUM_template_v2.rte`로 새 프로젝트. IFC 임포트(DirectShape) → `_ifc.rvt`.
- 도구: rvt-mcp(타이핑 도구·`revit_send_code_to_revit`), horizun-revit(납품 워크플로).
- 사용자 열린 문서는 건드리지 않는다.

## 4. 지음 시트 DWG
- `ZIUM_template.dwt` 기준. power-cad는 열린 도면이 있어야 그리며 새 도면/열기 명령이 없음 → 열린 도면이 없으면 ezdxf로 DXF 작성 후 ODA File Converter 27.1로 DWG 변환.
- Revit에서 직접 내보낼 때는 DWG 내보내기 설정 `ZIUM_DWG`(217개 레이어, R2018, mm) 사용.

## 5. 기록
- 상태는 `docs/pipeline/STATUS-YYYY-MM-DD.ko.md`, 지침은 `docs/guidelines/`, 드라이브 `내 드라이브\건축설계_파이프라인`·`지침`에 사본.
- 온톨로지 적재는 06번 문서.
